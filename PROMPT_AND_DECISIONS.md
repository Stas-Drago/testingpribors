# Промпт и принятые решения

## Что генерирует модель

System prompt задаёт роль редактора карточек B2B-каталога, русский язык и четыре поля ответа:
SEO-заголовок, SEO-описание, 3–5 поисковых запросов и коммерческий блок. Характеристики,
пропуски и предупреждения в ответ модели не включаются: эти поля собирает приложение из
проверенного входного объекта.

Модель обязана использовать только сведения из товара. В правилах отдельно запрещено
добавлять новые числовые значения и неподтверждённые единицы, диапазоны, точность, интерфейсы,
материалы, комплектацию, сертификаты, гарантии, режимы работы, совместимость и преимущества.
Если данных недостаточно для вывода о целевой аудитории или назначении, модель должна это
оговорить, а не додумывать.

## Разделение инструкций и исходных данных

Исходный `ProductInput` сериализуется в JSON и передаётся отдельным блоком как недоверенные
данные. Символы угловых скобок экранируются, чтобы товарный текст не мог закрыть delimiter.
Инструкции из названия, описания и характеристик не выполняются. Ключ API отсутствует в prompt.

## Структурированный ответ OpenAI

Клиент отправляет запрос на Chat Completions endpoint и передаёт JSON Schema через
`response_format: {type: json_schema, json_schema: {strict: true, ...}}`. Схема содержит ровно
четыре текстовых поля; `additionalProperties` запрещены, все свойства обязательны. Ответ затем
проверяется Pydantic и прикладным валидатором. Схема улучшает формат, но не гарантирует истинность
свободного текста. Используется поддерживаемый OpenAI Structured Outputs формат JSON Schema;
см. [официальную документацию OpenAI](https://developers.openai.com/api/docs/guides/structured-outputs).

По умолчанию используется `gpt-4o-mini`; модель, базовый URL и тайм-аут задаются настройками.
OpenAI SDK не требуется: HTTP-запрос выполняет `httpx`, поэтому легко тестируется mock-транспортом.
API key отправляется только в Authorization заголовке серверного запроса и не логируется.

## Проверки и контролируемое исправление

Проверяются типы и непустота полей, SEO-лимиты, количество поисковых фраз. Числовые токены
модельного текста сопоставляются со значениями входа после нормализации десятичной точки/запятой.
Неизвестные числа дают предупреждение для человека, но сами по себе не запускают повтор.
Если JSON-ответ или ограничения невалидны, `DraftService` делает ровно один запрос исправления
только четырёх генерируемых полей. Ошибки API и timeout не повторяются автоматически.

## Где находится исходный текст промпта

`app/services/prompt_builder.py` — системная инструкция, сериализация исходного JSON и запрос
исправления. Тесты в `tests/test_prompt_builder.py` проверяют границы доверия, отсутствие ключа
в данных и состав генерируемых полей. Транспорт и JSON Schema находятся в
`app/services/llm_client.py`.
