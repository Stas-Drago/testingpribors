# Ограничения и возможные улучшения

## Текущие ограничения

- Требуется доступ к OpenAI API и действующий API key; при недоступности генерация не работает.
- Входные данные передаются стороннему API. Заказчик должен проверить допустимость передачи,
  требования к хранению/обработке данных и конфигурацию аккаунта.
- Числовая сверка — эвристика: она может пропустить неподдержанное словесное утверждение и
  пометить допустимое число; она не доказывает достоверность семантики.
- Структурированный ответ, инструкции и одна попытка исправления не гарантируют отсутствия
  фактических ошибок. Ручная техническая проверка обязательна.
- Результаты OpenAI могут отличаться между моделями и версиями. Уже сохранённые в репозитории
  ответы были созданы предыдущей Ollama-интеграцией и не представляют оценку OpenAI.
- Прототип обрабатывает один товар за запрос. Нет базы данных, истории/сравнения версий,
  аутентификации, ролевой модели, пакетного импорта, CMS-интеграции и публикации.
- Настройки ключа и модели задаются окружением; нет интерфейса администрирования и ротации ключа.
- Кроссплатформенность предполагает Python 3.11+; точные версии зависимостей заданы диапазонами,
  универсальный lock-файл пока не ведётся.

## Возможные улучшения

1. Добавить CI-матрицу Windows, Ubuntu и macOS: pytest, Ruff, compileall и smoke-тест `/health`.
2. Зафиксировать воспроизводимые зависимости lock-файлом и протестировать пакет на версиях
   Python, поддерживаемых у заказчика.
3. После предоставления OpenAI key выполнить живую генерацию обоих примеров, обновить
   `examples/generated_results.md` и провести редакторскую/техническую сверку каждого предложения.
4. Добавить набор регрессионных примеров/оценок качества для проверки groundedness, полноты,
   русского языка и соблюдения длины перед сменой модели или промпта.
5. Усовершенствовать контроль фактов: маркировать утверждения ссылками на исходные поля,
   проверять предложения человеком, при необходимости использовать отдельную модель только
   как reviewer, не позволяя ей менять значения характеристик.
6. Добавить защищённые лимиты размера/частоты запросов, аутентификацию и политики хранения,
   если прототип будет развиваться в многопользовательский сервис.
7. Расширить поддержку каталожных форматов, пакетной загрузки и экспорта после согласования
   требований заказчика.
