# testingpribors

Тестовое задание для фирмы Союз-Прибор

## Генератор черновиков карточек товаров

Локальный прототип для подготовки B2B-карточки контрольно-измерительного прибора по
исходным данным. Архитектура и план реализации находятся в [`project.md`](project.md).

## Состояние

Проект реализуется по этапам. После каждого этапа запускаются его тесты; прогресс и
результаты записываются в `project.md`.

## Подготовка окружения

Требуется Python 3.11 или новее.

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install -e ".[dev]"
cp .env.example .env
```

В `.env` указаны локальная модель `qwen3:8b` и адрес Ollama. API-ключ не нужен; убедитесь,
что Ollama запущена и эта модель доступна (`ollama list`). Настройки можно изменить через
`OLLAMA_MODEL`, `OLLAMA_BASE_URL` и `LLM_TIMEOUT_SECONDS`. Файл `.env` исключён из Git.

## Запуск

```bash
uvicorn app.main:app --reload
```

Интерфейс доступен по адресу `http://127.0.0.1:8000`, описание API —
`http://127.0.0.1:8000/docs`. `/health` проверяет доступность приложения без обращения к Ollama.

## Тесты

Согласно правилам проекта, запускайте их в Docker:

```bash
docker compose -p product-card-generator run --rm tests
```

## Примеры и ограничения

- `examples/product_1.json` — пример манометра из условия.
- `examples/product_2.json` — данные второго товара (будут подтверждены источником).
- `examples/generated_results.md` — результаты для двух товаров после реализации API.

Модель не формирует структурированный список технических характеристик: он копируется
из входных данных. Свободный SEO- и коммерческий текст требует проверки контент-менеджером.
См. ограничения и актуальный прогресс в `project.md`.
